# 🧪 Roblox Test Creator Guide (Domain Layer)

## 🎯 Purpose & Scope
This skill provides deterministic rules for authoring, organizing, and executing **BDD Unit Tests** (`*.spec.lua` / `*.spec.luau`) inside the **Domain Layer** using **TestEZ** syntax and verified via the **Roblox Development Kit (RDK)**.

## 📌 When to Use
- Writing mandatory BDD unit tests for pure Luau Domain components, entities, calculators, and definitions.
- Verifying 100% test coverage before integrating Domain modules into Application UseCases.
- Executing unit tests in the terminal via `rdk test`.
- Testing immutability and discrete time-stepping (`deltaTime` injection).

## 🛑 When Not to Use
- **DO NOT** trigger for UI Presenter or View visual testing (belongs to Presentation Layer).
- **DO NOT** use for live multi-server network integration testing.
- **DO NOT** use for general Git version control operations.

## 📥 Inputs
- **Required**: Target Domain module to test, expected initial states, boundary conditions, edge cases, and mutation expectations.
- **Optional**: Custom overrides and error scenarios.

## 📋 Workflow
1. **Inspect**: Identify the target Domain module (Component, Entity, Standalone, or Definition).
2. **Decide**: Place the test file named `<DomainName>.spec.lua` directly inside the target domain's directory.
3. **Execute**: Structure BDD test blocks with TestEZ syntax:
   - `describe("<DomainName> Domain", ...)` root block.
   - `describe("Factory", ...)` verifying defaults and overrides.
   - `describe("Policies & Mutations", ...)` verifying immutability (`expect(original).to.equal(...)`).
   - `describe("Edge Cases", ...)` verifying clamping and error handling.
   - `describe("Time-Stepping", ...)` verifying discrete `dt` injection.
4. **Validate**: Run `rdk test src/shared/Domain/<DomainName>` and confirm 100% test passing.
5. **Report**: Output test execution summary and pass counts.

## 🔀 Decision Rules
- If testing time-based logic → Inject discrete `dt` / `deltaTime` numbers; NEVER use `task.wait()` or async delays.
- If testing state mutations → Verify that the original model remains untouched (immutability check).
- If testing platform-dependent code → Refactor logic into pure Domain first; NEVER call Roblox Engine APIs (`game`, `workspace`) inside domain specs.
- All test block descriptions (`describe`, `it`), failure assertion messages, and comments **MUST** be written in **standard professional English**.

## 🔍 Verification Checklist
- [ ] Verify all tests run in standard Luau environment via RDK without Studio dependencies.
- [ ] Verify 100% branch and policy coverage.
- [ ] Run runner: `rdk test` and verify zero failures.

## 📤 Output
- Consolidated `.spec.lua` file located alongside the target Domain module.
- 100% green test report generated by RDK test runner.
